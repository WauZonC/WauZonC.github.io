暑期参加了北京大学 Linux 俱乐部（LCPU）的「AI Infra」系列活动，从 CUDA 基础一路做到 Tensor Core 与 TileLang。这里把前几节的概念笔记整理成一篇，作业代码不在正文里展开。

## 执行模型：线程是怎么被组织起来的

写 CUDA 最先要建立的直觉是三层结构：**grid → block → thread**。kernel 启动时你指定 grid 与 block 的形状，硬件把每个 block 调度到某个 SM 上，block 内部的线程再按 32 个一组切成 warp 执行。

- **SIMT 不是 SIMD**：SIMD 是一条指令处理多个数据，SIMT 是多个线程各自执行同一条指令。硬件以 warp 为单位取指，所以同一 warp 内的线程如果走了不同的分支，就会串行化——这就是 warp divergence。
- **因此分支要尽量「同进同出」**：把条件分支写成不依赖线程编号的形式，或者让同一 warp 的线程走同一条路，往往比微调别的细节更有效。
- **block 的规模要能整除或至少不浪费 warp**：block 大小取 32 的整数倍是最省事的做法。

## 内存层级：性能差距主要在这里

CUDA 的内存层级从快到慢大致是：寄存器 → shared memory → L2 → global memory。真正决定性能的通常不是算力，而是**访存模式**。

- **coalescing（合并访存）**：一个 warp 的 32 个线程如果访问连续的地址，硬件能把它们合并成少数几次事务；如果地址跳跃，同样 32 次访问会退化成很多次事务。写 kernel 时优先让相邻线程访问相邻数据。
- **shared memory 用来做暂存与复用**：把需要反复读的数据先搬到 shared memory，可以减少 global 访问。但它有 bank 冲突的问题，按 32 个 bank 的分布去安排索引访问能避免。
- **occupancy 与延迟隐藏**：occupancy 是每个 SM 上驻留的活跃 warp 数。它的作用是「当一个 warp 等内存时，还有别的 warp 能顶上」。所以 occupancy 不是越高越好——如果 kernel 本来就是访存瓶颈，盲目提高占用率并不会变快。

## 两个经典模式

**grid-stride loop**：让每个线程处理多个元素，而不是「一个线程一个元素」。这样同一份 kernel 能适配任意数据规模，也减少了线程启动与结束的开销。

**block reduction（归约）**：把 256 个数的和算出来，最朴素的做法是让一个线程串行加。更好的写法是分层并行：先在线程内累加，再用 shared memory 做树形归约，最后用 warp shuffle 在寄存器之间完成最后几步。归约是理解「无锁并行」的入门题——顺序变了，结果也会略有不同，浮点加法不满足结合律，这点在需要严格精度时要注意。

**原子操作与直方图**：直方图这类有写冲突的问题可以用原子操作，也可以用「每个线程私有直方图 + 最后合并」来换更少冲突。两种写法各有一组 trade-off，取决于数据的分布。

## 几条我觉得最容易踩的点

- **计时陷阱**：kernel 启动是异步的，不 `synchronize` 就计时，量到的是启动开销而不是计算时间。
- **只优化 kernel、不看传输**：把数据从主机搬到设备的时间也算了进去，才发现瓶颈不在 kernel。
- **先看清瓶颈再优化**：先判断是访存、算力还是延迟受限，再决定是调 block 大小、改访存顺序，还是减少同步。
